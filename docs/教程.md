## 0. 先跑起来

### 0.1 这个项目是什么

`ezx-core` 是建立在 **EasyX** 之上的一个小型"界面底座"。EasyX 本身只提供最底层的画点、画线、贴图、取鼠标消息；这个项目在其上封装了 6 样东西：

| 模块 | 一句话作用 | 对应类 |
|---|---|---|
| 窗口 | 建窗、切全屏、拖大拖小后自动重建 | `Window` |
| 分辨率适配 | 按 1280×720 写坐标，窗口怎么变都自动缩放 | `Viewport` |
| 鼠标键盘 | 每帧收集输入，提供"刚按下 / 点击 / 双击 / 拖拽 / 滚轮" | `Input` |
| 图片 | 加载图片，支持原尺寸 / 拉伸 / 等比 / 铺满 | `Image` |
| 文本输入 | 光标、退格、过滤字符、长度限制、数值钳制 | `TextInput` |
| 页面 | 每个页面三件事：排版 / 逻辑 / 绘制 | `Page`、`Pages` |

它**不提供按钮外观**。按钮、面板、列表这些"长什么样"的东西，要你自己用矩形 + 文字 + 图片画出来（第 13 章有现成配方）。

整个库只有两个文件：

```
ezx-core/
├─ easyx_core.h      接口：所有类、函数长什么样
├─ easyx_core.cpp    实现：这些函数具体怎么干
├─ Directory.Build.targets  可选：复制到项目根，MSBuild 自动适配 /MT、/utf-8、库目录
├─ demo_main.cpp     示例程序，可直接运行
├─ res/              示例图片
├─ docs/             教程、原理、FAQ、编辑器
├─ editor/           UI 编辑器
└─ README.md         速查
```

### 0.2 一个窗口最小长什么样

新建一个空 C++ 项目，把 `easyx_core.h`、`easyx_core.cpp` 加进去，再写一个 `main.cpp`：

```cpp
#include "easyx_core.h"     // 这一行等于把整个库的"目录"抄进来
using namespace ezx;        // 后面写 Window 就行，不用写 ezx::Window

int main()
{
    Window::enableDpiAwareness();          // 高分屏不发糊（可选，但建议）

    Window win;                            // ① 创建"窗口对象"（还没真建窗）
    if (!win.open(1024, 640)) return 1;    // ② 真正建窗：客户区 1024×640
    win.setTitle("我的第一个 EasyX 窗口");

    Input in;                              // 输入收集器

    while (true)                           // ③ 主循环：一秒转几十圈
    {
        win.poll();                        // 处理窗口被拖大/最大化
        in.update();                       // 把这一帧的鼠标键盘消息全收进来
        if (in.keyDown(VK_ESCAPE)) break;  // 按 Esc 退出

        win.beginFrame(RGB(20, 22, 28));   // ④ 清屏（整窗涂成这个颜色）
        drawText(40, 40, "你好，EasyX！按 Esc 退出", 28, RGB(235, 240, 255));
        win.endFrame();                    // ⑤ 翻页 + 按 60 FPS 动态限帧
    }

    return 0;                              // win 析构 → 自动关窗口
}
```

逐行解释：

- `Window win;`：在栈上创建对象。此时还没有任何窗口，只是 C++ 对象。
- `win.open(...)`：内部调用 EasyX 的 `initgraph` 建窗，并开启**双缓冲**（先画到内存，最后一次性显示，避免闪烁）。返回 `false` 表示建窗失败。
- `while (true)`：界面程序的核心是"**每帧重画**"。每转一圈叫一帧。
- `win.poll()`：检查窗口尺寸有没有变。拖边框、最大化后，EasyX 的窗口会失效，这个函数负责重建。
- `in.update()`：把 Windows 消息队列里这一帧的鼠标/键盘消息全部取出来，存成 `Input` 的成员。
- `win.beginFrame(...)`：用背景色清空整个画面。**每帧都要清**，否则上一帧的内容会残留。
- `drawText(...)`：在屏幕坐标 `(40, 40)` 画一行字（左上角对齐）。
- `win.endFrame()`：`FlushBatchDraw()` 把后台缓冲翻到屏幕，然后按 `targetFps`（默认 60）**动态计算**这一帧还要等多久：先 `Sleep(剩余-1ms)`，最后 1ms 用 `yield` 精确等到点。它不会固定睡 10ms。
  `endFrame(10)` 是旧写法（固定 `Sleep(10)`），不同机器帧率会飘，不建议再用。

### 0.3 图片 30 秒版

先给结论，细节在第 6 章：

```cpp
Image bg;                       // 声明一个图片对象

// 必须在窗口建好之后再 load！
if (!bg.load("res/bg.png")) { /* 加载失败 */ }

bg.draw(0, 0);                          // 按原尺寸画在 (0,0)
bg.draw(Rect{0, 0, 1024, 640});         // 拉伸成 1024×640（可能变形）
bg.drawFit(Rect{0, 0, 1024, 640});      // 等比缩放，完整放进矩形（可能留边）
bg.drawCover(Rect{0, 0, 1024, 640});    // 等比缩放，铺满矩形（可能裁边）
```

如果用了 `Viewport`（推荐），就换成设计坐标：

```cpp
vp.image(bg, Rect{0, 0, 1280, 720});       // 拉伸
vp.imageFit(bg, Rect{0, 0, 1280, 720});    // 等比完整
vp.imageCover(bg, Rect{0, 0, 1280, 720});  // 等比铺满
```

图片路径是**相对"当前工作目录"**的，不是相对 `.cpp` 文件。VS 里按 F5 调试时，工作目录默认是工程目录（`.vcxproj` 所在文件夹）。详见 6.2。

## 1. 读代码前，补一点 C++

不用系统学完 C++，下面这些是读本项目**真正会碰到**的。每个概念都配了"本项目里对应哪段代码"。

### 1.1 `.h`、`.cpp`、编译、链接

- **`.h`（头文件）**：只写"长什么样"——类有哪些成员、函数叫什么、参数是什么。相当于**目录**。
- **`.cpp`（源文件）**：写"具体怎么干"——函数体。相当于**正文**。
- 编译器把每个 `.cpp` 单独编译成 `.obj`，最后**链接器**把所有 `.obj` 拼成 `.exe`。

```cpp
// easyx_core.h（目录）
int add(int a, int b);

// easyx_core.cpp（正文）
int add(int a, int b) { return a + b; }

// main.cpp（使用）
#include "easyx_core.h"
int x = add(1, 2);
```

`#include "easyx_core.h"` 不是"导入模块"，而是**把那个文件的内容原样复制到这一行**。所以头文件里写的东西，每个包含它的 `.cpp` 都能看到。

如果只在 `.h` 里声明、忘了把 `.cpp` 加进工程，编译能过，**链接会报 LNK2019（找不到外部符号）**。

### 1.2 `#pragma once`

```cpp
#pragma once
```

放在头文件第一行，表示"这个文件只展开一次"。防止 A 包含 B、B 又包含 A 时，同一个类被定义两遍。

### 1.3 `namespace` 和 `::`

`namespace` 是"姓氏"，避免重名：

```cpp
namespace ezx {
    class Window { /* ... */ };
}

ezx::Window win;          // 写全名
using namespace ezx;      // 或者声明"下面不加姓氏，默认用 ezx 的"
Window win2;              // 等价于 ezx::Window
```

`::` 读作"里面的"：`ezx::Window` = `ezx` 里面的 `Window`；`Window::open` = `Window` 类里面的 `open`。

> 本项目的所有东西都在 `ezx` 命名空间里。`using namespace ezx;` 写在 `.cpp` 顶部，后面就能少打字。

### 1.4 `struct` / `class`：把数据和函数打包

```cpp
struct Rect
{
    int x = 0;          // 成员变量（每个 Rect 对象各有一份）
    int y = 0;
    int w = 0;
    int h = 0;

    int right() const { return x + w; }   // 成员函数（所有 Rect 共用一份代码）
};

Rect r;                 // 创建一个 Rect 对象
r.x = 100;              // 用 . 访问成员
r.w = 200;
int rr = r.right();     // 调用成员函数，right() 里能直接看到 r 的 x/w
```

- `struct` 和 `class` 几乎一样，唯一区别：`struct` 默认成员是 **public**（外面能直接访问），`class` 默认 **private**。本项目大量使用 `struct`，就是为了让你能直接 `btn.x = 10;` 这样改。
- 成员函数里可以直接写 `x`、`w`，不需要写 `r.x`、`r.w`——它默认操作"当前这个对象"。
- `const` 写在参数列表后面（`int right() const`）表示"这个函数**不修改**对象"。只读函数都应该加，这样 `const Rect&` 也能调用它。

### 1.5 `.` 和 `->`

```cpp
Window win;
win.open(800, 600);       // 对象用 .

Window* p = &win;         // p 是指针，存的是 win 的地址
p->open(800, 600);        // 指针用 ->
```

读法：`p->open()` 等价于 `(*p).open()`。本项目里 `Window* g_win` 这种指针出现在 demo 中，用于在绘制函数里读取窗口模式。

### 1.6 引用 `&` 和 `const`

```cpp
void change(TextInput& t) { t.text = "hi"; }      // 引用：改的是原件
void show(const TextInput& t) { /* 只读 */ }       // const 引用：只读，且不复制

TextInput box;
change(box);      // box.text 真的变成 "hi"
```

- 参数写 `TextInput t`（不加 `&`）= **复制**一份，函数里怎么改都不影响外面，而且复制可能很贵。
- 写 `TextInput& t` = **别名**，函数里改的就是外面那个。
- 写 `const TextInput& t` = 别名 + 只读，最常用（既不复制，又不会被误改）。

> 看到 `const std::string& s` 不要怕：就是"借我看看这个字符串，我不改也不复制"。

### 1.7 默认参数

```cpp
bool open(int w, int h, WinMode mode = WinMode::Windowed);
```

调用时可以只写前两个：

```cpp
win.open(1024, 640);                          // mode 自动用 Windowed
win.open(1024, 640, WinMode::Fullscreen);     // 显式指定
```

默认值只能写在**声明**（`.h`）里，不能重复写在 `.cpp` 里。

### 1.8 `std::string`：会自动管理内存的字符串

```cpp
#include <string>

std::string s = "得分：";
s += std::to_string(120);      // 数字转字符串再拼接
int n = (int)s.size();         // 字节数，不是"字符数"
bool empty = s.empty();
```

⚠️ **中文一个汉字在 UTF-8 里通常占 3 个字节**。`s.size()` 数的是字节，不是字数。

本项目里的 `TextInput`：

- `text` 用 UTF-8 存；
- `cursor` 是**字节下标**（内部保证落在字符边界）；
- `maxLen` 和 `length()` 按**字符**算（中文算 1 个）。

所以中文可以正常输入，只是你自己遍历 `text` 时要注意别按字节乱切（用 `length()` 数字符，不要用 `size()`）。

### 1.9 `std::vector`：自动变长的数组

```cpp
#include <vector>

std::vector<int> v;
v.push_back(10);       // 尾部追加
v.push_back(20);
int a = v[0];          // 下标访问
int n = (int)v.size(); // 元素个数
```

本项目用 `std::deque`（双端队列）存页面。`deque` 在尾部 `push_back` 时**不会**让已经拿到的 `Page&` 失效：

```cpp
Page& home = pages.add("home");
pages.add("game");          // 用 deque，不会搬家
home.draw = ...;            // ✅ 仍然有效
```

但读别人的代码要小心：`std::vector` 变长时可能"搬家"（重新分配内存），之前拿到的引用/指针会**失效**。本项目的 `Pages` 改用 `deque` 就是为了避开这个坑（详见第 9 章）。

### 1.10 `std::function` 和 lambda

`std::function` 是"可以存起来的函数"。本项目用它把"页面要做什么"存进 `Page`：

```cpp
struct Page
{
    std::function<void(const Viewport&)> layout;   // 存一个"接收 Viewport、无返回值"的函数
    std::function<void(const Input&)>    update;
    std::function<void(const Viewport&)> draw;
};
```

赋值时通常用 **lambda**（匿名函数）：

```cpp
Page& home = pages.add("home");

home.layout = [](const Viewport& vp) {
    // 这里写排版
};

home.update = [](const Input& in) {
    // 这里写逻辑
};

home.draw = [](const Viewport& vp) {
    // 这里写绘制
};
```

- `[]` 叫"捕获列表"，决定 lambda 里能不能用外面的变量：
  - `[]`：不用外面的变量。
  - `[&]`：外面的变量按**引用**用（能改）。
  - `[=]`：按**值**复制进来（只读副本）。
  - `[&vp]`：只捕获 `vp` 的引用。
- `()` 里是参数，`{}` 里是函数体。
- `->` 后可写返回类型，通常省略。

⚠️ 捕获引用时，要保证被引用的对象活得比 lambda 久。**不要把 `main` 里的局部变量按引用捕获后，让页面活到 `main` 结束之后**。简单做法：页面里用全局变量/静态变量，或者捕获全局对象。

### 1.11 `enum class`：给数字起名字

```cpp
enum class WinMode
{
    Windowed,     // 普通窗口
    WorkArea,     // 铺满工作区（不盖任务栏）
    Fullscreen    // 无边框全屏
};

WinMode m = WinMode::Fullscreen;   // 必须写作用域
```

对比老式 `enum`，`enum class` 不会和别的名字冲突，也不能隐式转成 `int`。本项目里 `WinMode`、`Align` 都是这种。

### 1.12 构造函数 / 析构函数 / RAII

```cpp
class Window
{
public:
    Window() = default;    // 构造函数：创建对象时自动调用
    ~Window();             // 析构函数：对象销毁时自动调用

    Window(const Window&) = delete;             // 禁止复制
    Window& operator=(const Window&) = delete;  // 禁止赋值
};

Window::~Window()
{
    close();               // 离开作用域时自动关窗口
}
```

这套"对象出生时拿资源、死亡时自动还资源"的思路叫 **RAII**。好处：你不用手动记得 `closegraph()`。

```cpp
int main()
{
    Window win;            // 构造
    win.open(...);
    // ...
}                          // main 结束 → ~Window() → closegraph()
```

⚠️ `Window` 不允许复制：

```cpp
Window a;
Window b = a;      // ❌ 编译错误（一个程序只能有一个绘图窗口）
```

### 1.13 `shared_ptr`：共享所有权

`Image` 内部是：

```cpp
std::shared_ptr<IMAGE> img_;
```

意思是：多个 `Image` 对象可以**共享同一份像素数据**，最后一个销毁时才真正释放。

```cpp
Image a;
a.load("res/icon.png");

Image b = a;       // 复制：b 和 a 指向同一张图，不会重新读盘
```

复制很便宜，适合放进 `std::vector` 或结构体里。`Image` 的 `load` 成功后，旧的图会被自动释放（如果没别人引用）。

### 1.14 `Rect{ x, y, w, h }` 这种写法

```cpp
struct Rect { int x; int y; int w; int h; };

Rect r{ 100, 200, 300, 60 };     // 按顺序初始化：x=100, y=200, w=300, h=60
Point p{ 10, 20 };
```

这叫"聚合初始化"，顺序必须和成员声明顺序一致。本项目大量使用，看到 `Rect{...}` 就按 `x, y, 宽, 高` 读。

## 2. 坐标与矩形：Point / Rect

### 2.1 屏幕坐标系

和数学课相反，**y 轴向下**：

```
(0,0) ──────────→ x 变大
  │
  │
  ↓
 y 变大
```

窗口客户区左上角是 `(0,0)`，右下角是 `(width-1, height-1)`。

### 2.2 `Point`

```cpp
struct Point
{
    int x = 0;
    int y = 0;
};
```

一个点。鼠标位置、矩形中心都用它。

### 2.3 `Rect`

```cpp
struct Rect
{
    int x = 0;      // 左上角
    int y = 0;
    int w = 0;      // 宽
    int h = 0;      // 高

    int right()  const { return x + w; }     // 右边界（不含）
    int bottom() const { return y + h; }     // 下边界（不含）
    Point center() const { return Point{ x + w / 2, y + h / 2 }; }

    bool contains(int px, int py) const { return px >= x && px < x + w && py >= y && py < y + h; }
    bool contains(const Point& p) const { return contains(p.x, p.y); }
    bool empty() const { return w <= 0 || h <= 0; }

    Rect inset(int d) const;                 // 四周各缩进 d
    Rect inset(int dx, int dy) const;        // 横向缩 dx，纵向缩 dy
    Rect centered(int cw, int ch) const;     // 在自身内部居中放一个 cw×ch 的矩形
    Rect takeLeft(int partW) const;          // 取左边一条
    Rect takeRight(int partW) const;         // 取右边一条
    Rect takeTop(int partH) const;
    Rect takeBottom(int partH) const;
};
```

几个容易混的点：

1. `right()` 是 `x + w`，**不包含**这一列像素。所以 `Rect{0,0,100,50}` 包含 `x=0..99`，不包含 `x=100`。
2. `contains(100, 10)` 对上面这个矩形返回 `false`。
3. 矩形的 `w/h` 可以是 0 或负数，此时 `empty()` 为 `true`，绘制函数通常会直接跳过。

### 2.4 常用小工具

```cpp
Rect panel{ 100, 80, 400, 300 };

Rect inner  = panel.inset(20);          // {120, 100, 360, 260}
Rect title  = panel.takeTop(60);        // {100, 80, 400, 60}
Rect footer = panel.takeBottom(40);     // {100, 340, 400, 40}
Rect btn    = panel.centered(200, 50);  // 在 panel 正中间放 200×50
```

### 2.5 等分：`splitRow` / `splitCol`

做一排按钮时不用手算：

```cpp
Rect row{ 0, 600, 1280, 80 };
std::vector<Rect> cells = splitRow(row, 3, 20);   // 3 份，间距 20

// cells[0] = {0,   600, 413, 80}
// cells[1] = {433, 600, 413, 80}
// cells[2] = {866, 600, 414, 80}   ← 最后一个吃掉除不尽的余数
```

`splitCol` 是纵向等分。它们返回 `std::vector<Rect>`，用 `cells[i]` 取。

## 3. 窗口：Window

### 3.1 生命周期

```cpp
Window win;                      // 1. 构造（还没窗口）
win.onResize([](int w, int h) {  // 2. 先注册"尺寸变了"的回调
    // 重新算布局
});
if (!win.open(1024, 640))        // 3. 建窗 + 开双缓冲
    return 1;

while (true)
{
    win.poll();                  // 4. 每帧检查窗口尺寸
    win.beginFrame(...);         // 5. 清屏
    // 画东西
    win.endFrame();              // 6. 翻页 + 动态限帧
}                                // 7. 离开作用域 → ~Window → 关窗
```

### 3.2 建窗：`open`

```cpp
bool open(int w, int h, WinMode mode = WinMode::Windowed);
```

| 模式 | 含义 | `w/h` 参数 |
|---|---|---|
| `WinMode::Windowed` | 普通窗口：有标题栏，可拖边缩放、最大化 | 客户区大小 |
| `WinMode::WorkArea` | 带标题栏，铺满工作区（任务栏还在） | 被忽略 |
| `WinMode::Fullscreen` | 无边框，铺满整块屏幕（盖住任务栏） | 被忽略 |

返回 `false` 通常是 EasyX 初始化失败（极少见）。

`open()` 内部会：

1. 调 `initgraph` 建窗；
2. 补上 `WS_MAXIMIZEBOX | WS_THICKFRAME`（否则最大化按钮是灰的）；
3. `flushmessage()` 清掉建窗时积压的鼠标消息；
4. `BeginBatchDraw()` 开双缓冲。

> ⚠️ `open()` **不会**触发 `onResize`。建窗后要自己调一次排版（demo 里在 `main` 中手动 `vp.fit` + `pages.layoutAll`）。

### 3.3 每帧：`poll`

```cpp
bool poll();
```

**每帧必须调用。** 它做的事：

1. 读当前客户区尺寸；
2. 如果和上次记录的一样 → 什么都不做；
3. 如果变了，且连续两帧一致（消抖）→ 销毁旧窗口、按新尺寸重建、重开双缓冲；
4. 调用 `onResize(新宽, 新高)`。

为什么需要"连续两帧一致"：拖边框时尺寸每帧都在变，如果每变一次就重建，会疯狂闪烁。

返回 `true` 表示这一帧重建过。

> `poll()` 只在 `Windowed` 模式下工作。全屏/工作区模式下窗口尺寸不会变，直接返回。

### 3.4 尺寸变化回调：`onResize`

```cpp
void onResize(std::function<void(int w, int h)> cb);
```

参数是**新的客户区宽高**。典型用法：

```cpp
win.onResize([&](int w, int h) {
    vp.fit(w, h);              // 重算缩放
    pages.layoutAll(vp);       // 所有页面重新排版
});
```

什么时候会调用：

- `poll()` 检测到尺寸变化并重建后；
- `applyMode()` 切换模式后。

**不会**在 `open()` 后自动调用。

### 3.5 切换模式：`applyMode`

```cpp
bool applyMode(WinMode mode, int w = 0, int h = 0);
```

运行时切全屏/窗口：

```cpp
if (win.mode() == WinMode::Fullscreen)
    win.applyMode(WinMode::Windowed, 1024, 640);
else
    win.applyMode(WinMode::Fullscreen);
```

`w/h` 传 0 表示"用上次窗口模式的尺寸"。成功后会自动调用 `onResize`。

### 3.6 最小化 / 最大化 / 还原

```cpp
win.minimize();
win.maximize();
win.restore();
```

### 3.7 每帧开头结尾

```cpp
void beginFrame(COLORREF bg = CLR_INVALID);

void endFrame();              // 动态限帧（推荐）
void endFrame(int delayMs);   // 旧写法：固定 Sleep(delayMs)
void setTargetFps(int fps);   // 默认 60；0 = 不限帧
```

- `beginFrame(bg)`：把整窗涂成 `bg`。**不传参 = 黑色**（注意：本库没有全局主题，默认就是黑）。
- `endFrame()`：先 `FlushBatchDraw()`，再按目标帧率算：

  ```
  frameTime = 1000000 / targetFps   微秒（60 FPS → 16666 微秒）
  deadline  = 上一帧结束时间 + frameTime
  如果现在还没到 deadline：
      先 Sleep(剩余毫秒 - 1)
      最后 1ms 用 yield 自旋等到 deadline
  ```

  这样每帧间隔是**动态计算**的，不会像固定 `Sleep(10)` 那样在不同机器上飘。
- 第一帧只记录起点，不睡；如果这一帧本身已经超过 `frameTime`（比如卡了），就不睡，帧率自然下降。
- `open()` 时调用 `timeBeginPeriod(1)` 提高计时精度，`close()` 时 `timeEndPeriod(1)` 还原。
- `setTargetFps(30)` / `setTargetFps(144)` 可改目标；`setTargetFps(0)` 不限帧（会跑满 CPU）。
- `endFrame(10)` 是兼容旧代码的固定睡眠，不推荐；它会把实际帧率限制在“约 10ms + 系统精度”的水平。

### 3.8 其它

| 调用 | 作用 |
|---|---|
| `win.setTitle("x")` | 改标题；窗口重建后会自动恢复（内部记住了） |
| `win.width()` / `win.height()` | 当前客户区宽高 |
| `win.mode()` | 当前模式 |
| `win.alive()` | 窗口是否还在 |
| `win.handle()` | 原生 `HWND`（一般不用） |
| `Window::enableDpiAwareness()` | 高分屏不发糊，**启动时调一次** |

### 3.9 无边框窗口 / 全屏任务栏

`WinMode::Fullscreen` 就是**无边框**模式：去掉标题栏和缩放边框、铺满整块屏幕，并且**置顶**（`HWND_TOPMOST`），所以能盖住任务栏。

如果你切了全屏还能看到任务栏，检查：

1. 用的是 `WinMode::Fullscreen`，不是 `WinMode::WorkArea`（后者故意保留任务栏）；
2. 代码是当前版本（`Window::create` 里 Fullscreen 分支用了 `HWND_TOPMOST`）；
3. 按 F11 时确实调用了 `win.applyMode(WinMode::Fullscreen)`。

本项目**没有**“无边框但非全屏”的独立模式。要做这种窗口，得自己去标题栏，并自己处理拖动/关闭，属于额外工作。

### 3.10 不要做的事

- ❌ 不要自己调 `closegraph()`。`Window` 的析构会做，你调了之后 `Window` 内部的 `hWnd_` 还指着旧窗口，后续绘制会出问题。
- ❌ 不要同时创建两个 `Window`。EasyX 同一时刻只有一个绘图窗口。
- ❌ 不要在 `Window` 析构之后还使用 `win`。
- ❌ 不要把 `Window` 放进 `std::vector`（它禁止复制）。

## 4. 分辨率适配：Viewport

### 4.1 为什么需要它

假设你按 1280×720 设计界面，用户把窗口拖成 1600×900。如果你直接写 `drawText(640, 360, ...)`，文字会跑到左上角，界面全乱。

`Viewport` 的做法：**你永远按设计尺寸写坐标，它负责换算**。

```
scale = min(窗口宽 / 设计宽, 窗口高 / 设计高)
```

- 窗口比设计大 → 整体放大；
- 窗口比设计小 → 整体缩小；
- 宽高比不一致 → 多出来的地方留黑边（letterbox）。

例子：

```
设计 1280×720，窗口 1024×768
scale = min(1024/1280, 768/720) = min(0.8, 1.0667) = 0.8
设计区实际大小 = 1024×576
上下各留 (768-576)/2 = 96 像素黑边
```

### 4.2 基本用法

```cpp
Viewport vp;
vp.setDesign(1280, 720);       // 设计分辨率（默认就是 1280×720）

// 窗口建好后、以及每次窗口尺寸变化后：
vp.fit(win.width(), win.height());
```

配合 `Window`：

```cpp
Window win;
Viewport vp;

vp.setDesign(1280, 720);

win.onResize([&](int w, int h) {
    vp.fit(w, h);
    pages.layoutAll(vp);
});

win.open(1024, 640);
vp.fit(win.width(), win.height());   // open 不会触发 onResize，手动来一次
```

### 4.3 用设计坐标画东西

```cpp
vp.fill(Rect{ 40, 40, 300, 80 }, RGB(40, 44, 54));            // 实心矩形
vp.frame(Rect{ 40, 40, 300, 80 }, RGB(90, 120, 180), 2);      // 空心框（线宽 2）
vp.text(60, 60, "你好", 28, RGB(255, 255, 255));               // 文字（左上角）
vp.textIn(Rect{ 40, 40, 300, 80 }, "居中", 28, RGB(255, 255, 255)); // 在矩形里垂直居中
vp.textIn(rect, "右对齐", 28, color, Align::Right);             // 水平右对齐

vp.image(bg, Rect{ 0, 0, 1280, 720 });       // 图片拉伸铺满
vp.imageFit(logo, Rect{ 565, 60, 150, 150 }); // 图片等比放入
vp.imageCover(bg, Rect{ 0, 0, 1280, 720 });   // 图片等比铺满
```

### 4.4 鼠标坐标要反算

`Input` 给的鼠标位置是**窗口客户区坐标**（屏幕像素），而你的按钮是设计坐标。所以：

```cpp
Point p = vp.toDesign(in.pos());          // 窗口坐标 → 设计坐标

Rect btn{ 540, 300, 200, 60 };
if (btn.contains(p)) { /* 点中按钮 */ }
```

或者更简单：把设计矩形换算成屏幕矩形，再和鼠标比：

```cpp
if (vp.R(btn).contains(in.pos())) { /* 点中 */ }
```

两种写法等价，第二种少一次坐标转换。

### 4.5 黑边（letterbox）怎么去掉

黑边不是 bug，是 **letterbox**：设计比例和窗口比例不一致时，`Viewport` 选择“完整显示”，多出来的地方留边。

例子：设计 1280×720（16:9），窗口 1024×640（16:10）：

```
scale = min(1024/1280, 640/720) = min(0.8, 0.888) = 0.8
设计区 = 1024×576
上下各留 (640-576)/2 = 32 像素黑边
```

全屏时也一样：16:9 的屏幕没有黑边；16:10 的屏幕会上下留边。

**三种处理方式**：

1. **让比例一致**：窗口/设计都用 16:9（例如 `win.open(1024, 576)`）。
2. **把黑边涂成背景色**（看起来像没有）：
   ```cpp
   win.beginFrame(RGB(8, 8, 12));
   vp.paintLetterbox(RGB(8, 8, 12));
   ```
3. **改成铺满、裁边**（没有黑边，但边缘内容可能被裁）：
   ```cpp
   vp.setScaleMode(ScaleMode::Cover);   // 默认是 Contain
   ```
   `Cover` 用 `max` 而不是 `min` 算缩放，左右或上下会超出窗口被裁掉。重要内容要放在“安全区”里，别贴边。

### 4.6 API 速查

| 调用 | 作用 |
|---|---|
| `setDesign(w, h)` | 设置设计分辨率 |
| `setScaleMode(Contain / Cover)` | 留黑边 / 裁边铺满 |
| `fit(winW, winH)` | 重算缩放和偏移（窗口尺寸变了就调） |
| `scale()` | 当前缩放比例 |
| `offsetX()` / `offsetY()` | 设计区左上角在窗口里的偏移 |
| `area()` | 设计区占的屏幕矩形 |
| `toDesign(screenX, screenY)` | 窗口坐标 → 设计坐标 |
| `inside(screenX, screenY)` | 鼠标是否在设计区内（黑边上返回 false） |
| `R(rect)` | 设计矩形 → 屏幕矩形 |
| `fill` / `frame` | 用设计坐标画矩形 |
| `text` / `textIn` | 用设计坐标画字 |
| `image` / `imageFit` / `imageCover` | 用设计坐标画图 |
| `paintLetterbox(color)` | 涂黑边 |

### 4.7 三条铁律

1. **用了 `Viewport`，布局和绘制就全用设计坐标**，不要一会儿设计坐标、一会儿 `getwidth()`。
2. **鼠标必须先换算**（`toDesign` 或 `vp.R(...).contains`），否则命中判断全错。
3. **窗口尺寸一变就 `fit` + 重新排版**，在 `onResize` 里做。

> 小字提醒：字号也会被缩放。设计字号 18 在 0.75 倍窗口上只有约 13 像素，可能看不清。小窗口下要么少放字，要么给字号设下限。

## 5. 文字

### 5.1 字号 = 像素高度

EasyX 的 `settextstyle(高, 宽, 字体)` 里，**高就是字符的像素高度**。所以：

```cpp
drawText(100, 100, "五子棋", 40, RGB(255, 255, 255));
// "五子棋" 大约高 40 像素、宽 120 像素
```

本项目里 `fontSize` 全部按"像素高度"理解，不用做 DPI 换算。

### 5.2 设置默认字体

```cpp
setDefaultFont("微软雅黑");     // 启动时调一次；默认是"宋体"
```

之后所有 `drawText` / `textWidth` 都用它，除非单独传 `font`。

### 5.3 画字与量字

```cpp
void drawText(int x, int y, const std::string& s, int fontSize, COLORREF color,
              const std::string& font = "");

int textWidth(const std::string& s, int fontSize, const std::string& font = "");
int textHeight(const std::string& s, int fontSize, const std::string& font = "");
```

- `x, y` 是文字**左上角**，不是基线。
- `font` 传空 = 用 `defaultFont()`。
- `textWidth`/`textHeight` 会临时切换 EasyX 当前字体。量完再画没问题；但如果你量完后要用 EasyX 原生 `outtextxy`，记得自己重设字体。

居中不用自己算：

```cpp
// 不用 Viewport 时：
int w = textWidth("标题", 32);
drawText((getwidth() - w) / 2, 80, "标题", 32, RGB(255, 255, 255));

// 用 Viewport 时：
vp.textIn(Rect{ 0, 60, 1280, 60 }, "标题", 32, RGB(255, 255, 255));
```

### 5.4 中文与编码

库内部按这个顺序处理字符串：

1. 纯 ASCII → 直接转；
2. 合法 UTF-8 → UTF-8 → UTF-16 →（多字节工程再转 ANSI）；
3. 不是合法 UTF-8（说明源码没开 `/utf-8`，字面量被编成了 GBK）→ 当系统 ANSI 用。

所以无论你的工程是 UTF-8 字面量还是 GBK 字面量，中文都能显示。**源文件建议保存为 UTF-8 带 BOM**，否则 MSVC 在中文系统上会按 GBK 解析 UTF-8 源码，轻则警告 C4819，重则报假语法错。

如果字符串是**运行时从文件读的**，请确保文件是 UTF-8（库优先按 UTF-8 解析）。

### 5.5 不支持自动换行

`drawText` 只画一行。长文本要自己拆：

```cpp
drawText(x, y,       "第一行", 20, color);
drawText(x, y + 28,  "第二行", 20, color);
```

或者按宽度手动折行（本项目没提供，需要自己写）。

## 6. 图片（重点）

这一章回答三个问题：**图片放哪、怎么加载、怎么画**。

### 6.1 图片是什么

在程序里，图片就是一个"像素矩阵"：

- 每个像素 4 个字节：红、绿、蓝、透明度（RGBA）；
- 一张 1920×1080 的图约占 `1920 × 1080 × 4 ≈ 8.3 MB` 内存；
- 文件格式（png/jpg/bmp）只是"压缩存储方式"，加载后都变成这个矩阵。

本项目用 EasyX 的 `IMAGE` 存像素，外面包一层 `Image` 类，负责加载、透明混合、绘制。

### 6.2 图片放哪、路径怎么算

**放哪**：随便，通常放在工程目录下的 `res/`：

```
你的工程/
├─ easyx_core.h
├─ easyx_core.cpp
├─ demo_main.cpp
└─ res/
   ├─ bg.png
   └─ logo.png
```

**路径规则**：`"res/bg.png"` 是**相对"当前工作目录"**的，不是相对 `.cpp` 文件，也不一定是相对 `.exe`。

| 启动方式 | 当前工作目录 | `"res/bg.png"` 实际指向 |
|---|---|---|
| VS 里按 F5 / Ctrl+F5 | 工程目录（`.vcxproj` 所在文件夹） | `<工程目录>\res\bg.png` |
| 双击 exe | exe 所在目录 | `<exe目录>\res\bg.png` |
| 命令行 `cd` 到某目录再运行 | 那个目录 | `<那个目录>\res\bg.png` |
| 被别的程序启动 | 由启动方决定 | 不确定 |

所以：

- **在 VS 里调试**：把 `res` 放在 `.vcxproj` 旁边就行。
- **发给别人 / 双击运行**：把 `res` 和 exe 放在同一层，整个文件夹一起发。
- **不想折腾路径**：用绝对路径。

绝对路径写法（**只适合本机调试，别用于发布**）：

```cpp
img.load("D:/游戏开发/00_自研引擎/ezx-core/res/bg.png");      // 正斜杠，最省事
img.load("D:\\游戏开发\\00_自研引擎\\ezx-core\\res\\bg.png"); // 反斜杠要写两个
```

> C++ 字符串里 `\` 是转义符，`\n` 是换行、`\t` 是制表符。所以 Windows 路径要么写 `\\`，要么写 `/`。

**打包发布：相对 exe 定位（推荐）**

本库提供了两个函数：

```cpp
std::string appDir();                    // exe 所在目录（UTF-8，带结尾斜杠）
std::string assetPath("res/bg.png");     // appDir() + "res/bg.png"
```

用法：

```cpp
img.load(ezx::assetPath("res/bg.png"));
```

这样不管从哪个目录启动（双击、快捷方式、别人电脑），都会去 **exe 旁边**找 `res`，不依赖“当前工作目录”。

发布时这样放：

```
发布文件夹/
├─ 你的程序.exe
└─ res/
   ├─ bg.png
   └─ logo.png
```

注意事项：

- 用 **Release + `/MT`** 编译；`/MT` 不依赖 VC++ 运行库安装包（`/MD` 则需要）。
- 绝对路径 `D:\...` 只适合你本机调试，发给别人一定找不到。
- Windows 文件名**大小写不敏感**，但打包/解压到某些工具时可能变；统一用小写 `res/` 最稳。
- `appDir()` 内部用 `MAX_PATH`（260 字符）；超长路径的极端情况不支持。
- 如果图片想“藏进 exe”，需要把图片编译成 Windows 资源（`.rc` + `FindResource`），再用 GDI+ 从内存解码；本项目没封装，初学者不建议。

**VS 调试时的工作目录**：项目属性 → 调试 → 工作目录，默认 `$(ProjectDir)`。如果 `res` 放在项目目录，F5 用 `"res/bg.png"` 就行；如果 `res` 放在输出目录，把工作目录改成 `$(OutDir)`，或用 `assetPath`。

### 6.3 加载：`Image::load`

```cpp
class Image
{
public:
    bool load(const std::string& path, int w = 0, int h = 0);

    bool ok() const;
    int  width()  const;
    int  height() const;

    void draw(int x, int y) const;          // 原尺寸
    void draw(const Rect& dst) const;       // 拉伸铺满矩形
    void drawFit(const Rect& dst) const;
    void drawCover(const Rect& dst) const;
};
```

基本用法：

```cpp
Image bg;
if (!bg.load("res/bg.png"))
{
    // 加载失败：路径不对、文件不存在、格式不支持……
}
else
{
    // 成功：bg.width() / bg.height() 是图片尺寸
}
```

要点：

1. **加载和绘制都放在 `win.open()` 之后**（demo 的做法）。绘制图片必须要有 EasyX 的绘图环境；加载本身虽然有些 EasyX 版本不建窗也能用，但没必要冒这个险。
2. `load` 返回 `bool`，**一定要检查**。失败时不弹系统对话框（内部先检查了文件是否存在），但图片就是空的，`draw` 什么也不画。
3. 支持 png / jpg / bmp 等常见格式（EasyX 走 GDI+ 解码）。**要透明就用 png**；jpg 没有透明通道。
4. 加载失败**不会**破坏之前已经加载成功的图（内部只有成功才替换）。
5. 空路径、文件不存在 → 直接返回 `false`。

**加载时缩放**：

```cpp
bg.load("res/bg.png", 640, 360);    // 加载时就缩成 640×360
```

- 只有 **宽和高都大于 0** 才会缩放；只传一个会被忽略。
- 如果原图宽高比和 `640:360` 不一致，会被**拉伸变形**。
- 好处：省内存、绘制快；坏处：缩放质量由 EasyX 决定，且不能再无损放大。

**什么时候加载**：

- 程序启动、窗口建好后加载一次，存到全局/成员变量里，之后每帧直接画。
- **不要每帧 `load`**——每帧读盘 + 解码会让程序卡死。

```cpp
Image g_bg;       // 全局（或某个类的成员）

int main()
{
    Window win;
    if (!win.open(1024, 640)) return 1;

    if (!g_bg.load("res/bg.png")) return 1;   // 只加载一次

    while (true) { /* 每帧 g_bg.draw(...) */ }
}
```

### 6.4 画出来：四种方式

假设原图是 `300×300`，目标矩形是 `300×120`：

| 调用 | 效果 | 会变形？ | 会留边？ | 会裁切？ |
|---|---|---|---|---|
| `draw(x, y)` | 按原尺寸画 | 否 | 否 | 否 |
| `draw(rect)` | 拉伸到目标大小 | **是** | 否 | 否 |
| `drawFit(rect)` | 等比缩放，完整放进矩形 | 否 | **可能** | 否 |
| `drawCover(rect)` | 等比缩放，铺满矩形 | 否 | 否 | **可能** |

图示：

```
目标框 300×120，原图 300×300

draw(rect)      → 图被压扁成 300×120          [填满，比例失真]
drawFit(rect)   → 图缩成 120×120，左右留白     [完整，可能留边]
drawCover(rect) → 图保持 300×300，上下被裁掉   [填满，可能裁切]
```

怎么选：

- **背景图**：`drawCover`（填满窗口，裁掉一点没关系）。
- **logo / 图标**：`drawFit`（必须完整显示）。
- **九宫格、面板底图**：通常 `draw(rect)` 拉伸，或者用 9-slice（本项目没封装）。
- **精确像素画**：`draw(x, y)` 原尺寸，或设计时就按整数倍缩放。

用 `Viewport` 时：

```cpp
vp.image(bg, rect);        // = bg.draw(vp.R(rect))
vp.imageFit(logo, rect);
vp.imageCover(bg, rect);
```

`rect` 是**设计坐标**，`Viewport` 会换算成屏幕矩形再画。

### 6.5 透明（png 的 alpha 通道）

EasyX 原生的 `putimage` 不认 alpha 通道，透明区域会被画成黑色。本库在 `Image` 里自己做了混合：

```
结果颜色 = 前景颜色 × alpha + 背景颜色 × (1 - alpha)
```

- `alpha = 0`：完全透明，保留背景；
- `alpha = 255`：完全不透明，直接覆盖；
- `0 < alpha < 255`：半透明，按比例混合。

实现细节（你不需要改，但知道有好处）：

1. `load` 时扫一遍所有像素，只要发现一个 `alpha != 255`，就把这张图标成"带透明"；
2. 带透明的图，`draw` 时逐像素读取源图和当前绘图缓冲，做混合；
3. 不带透明的图（jpg、或者 alpha 全 255 的 png）走 EasyX 原生 `putimage`，快很多。

所以：

- **要做透明图标，必须用 png，并且导出时保留 alpha 通道**。
- 如果 png 是从白底截图来的，白色区域 alpha=255，不会透明——看起来就是"白底方块"。
- jpg 永远没有透明通道，透明区域通常变成白色或黑色。

**性能提醒**：透明混合是 CPU 逐像素做的。

- 一张 1920×1080 的半透明图，每帧要处理约 207 万像素；
- 60 帧/秒就是 1.2 亿次像素运算，很容易掉帧。

建议：

- **全屏背景不要用带透明的 png**。用 jpg，或者导出时把 alpha 去掉（全 255）。
- 半透明只用在图标、按钮、局部面板上（几百×几百像素）。
- 如果背景 + logo 永远一起出现，干脆在图片软件里合成一张图。
- 加载时预缩放（`load(path, w, h)`）能减少绘制时的目标像素数。

### 6.6 生命周期、拷贝、性能

**拷贝是共享的**：

```cpp
Image a;
a.load("res/icon.png");

Image b = a;          // 共享同一份像素，不重新读盘
Image c;
c = a;                // 同样共享
```

最后一个 `Image` 销毁时才释放像素。所以把 `Image` 放进结构体、`std::vector`、按值传参都不心疼。

**全局图片的析构顺序**：

```cpp
Window win;           // 先声明
Image  bg;            // 后声明
// 离开作用域时：先析构 bg，再析构 win（后声明先析构）
```

这样图片先释放、窗口后关，最稳。demo 里 `g_bg`/`g_logo` 是全局变量，会在 `main` 结束后才析构；EasyX 的 `IMAGE` 析构只释放内存，不依赖窗口，通常也没问题。但如果你不放心，就按"先 Window 后 Image"的顺序声明成局部变量。

**性能清单**：

| 做法 | 影响 |
|---|---|
| 每帧 `load` | 极慢，绝对不要 |
| 大图带 alpha 全屏绘制 | 慢，逐像素混合 |
| 图片尺寸远大于显示尺寸 | 浪费内存；加载时预缩放 |
| 同一张图加载多次 | 浪费内存；共享同一个 `Image` 对象 |
| 每帧画很多小图 | 通常没问题 |

### 6.7 用图片做按钮（完整例子）

库不提供按钮，但用 `Image` + `Rect` + `Input` 写一个只要 20 行：

```cpp
#include "easyx_core.h"
using namespace ezx;

struct ImageButton
{
    Rect  rect;                    // 设计坐标
    Image icon;                    // 按钮上的图
    bool  hovered = false;

    // 每帧调用：更新悬停状态，返回"这一帧有没有点它"
    bool update(const Input& in, const Viewport& vp)
    {
        hovered = vp.R(rect).contains(in.pos());
        return hovered && in.clicked();
    }

    void draw(const Viewport& vp) const
    {
        vp.fill(rect, hovered ? RGB(64, 88, 136) : RGB(34, 42, 62));
        vp.frame(rect, RGB(96, 128, 200), 2);
        vp.imageFit(icon, rect.inset(10));
    }
};

int main()
{
    Window::enableDpiAwareness();

    Window win;
    Viewport vp;
    Input in;
    ImageButton btn;

    vp.setDesign(1280, 720);
    win.onResize([&](int w, int h) { vp.fit(w, h); });

    if (!win.open(960, 540)) return 1;
    win.setTitle("图片按钮");

    vp.fit(win.width(), win.height());

    btn.rect = Rect{ 540, 320, 200, 80 };
    if (!btn.icon.load("res/logo.png"))   // 项目自带的图；也可以换成你自己的图标
        return 1;                         // 图片没找到，直接退出（初学先这样）

    while (true)
    {
        win.poll();
        in.update();
        if (in.keyDown(VK_ESCAPE)) break;

        if (btn.update(in, vp))
        {
            // 点中了：这里写你的逻辑
            win.setTitle("点到了！");
        }

        win.beginFrame(RGB(16, 18, 24));
        vp.paintLetterbox(RGB(16, 18, 24));
        btn.draw(vp);
        win.endFrame();
    }

    return 0;
}
```

注意几个细节：

- `btn.update` 用的是 `vp.R(rect).contains(in.pos())`：设计矩形换算成屏幕矩形，再和鼠标（屏幕坐标）比。
- `in.clicked()` 是"按下并在 6 像素内松开"，比 `down()` 更适合按钮。
- `btn.draw` 里 `rect.inset(10)`：图标四周留 10 像素内边距（设计坐标）。
- 图片在 `win.open()` 之后才 `load`。

### 6.8 图片问题排查表

| 现象 | 最可能的原因 | 解决 |
|---|---|---|
| `load` 返回 `false` | 路径不对 / 文件不存在 / 文件名大小写 | 打印当前工作目录；先用绝对路径试 |
| `load` 成功但屏幕没图 | 忘了 `draw`；画在 `beginFrame` 之前；被背景盖住 | 检查绘制顺序，背景先画、图后画 |
| 图是黑块 | 用了带透明的 png，但绘制环境不对；或图本身是黑的 | 换 jpg 试；确认在 `open` 之后画 |
| 图标四周有白边/黑边 | 图片本身不是透明底 | 用图片软件导出真正的 png 透明图 |
| 图被压扁/拉长 | 用了 `draw(rect)` 拉伸 | 改用 `drawFit` 或 `drawCover` |
| 图有锯齿 | 缩放比例不是整数；原图太小 | 用 2 倍图；加载时预缩放 |
| 双击 exe 找不到图 | 工作目录不是工程目录 | 把 `res` 放到 exe 旁边，或用绝对路径 |
| 切全屏后图没了 | 绘制代码没在每帧执行；或页面切换了 | 检查 `draw` 是否每帧都调 |
| 中文路径加载失败 | 路径编码问题 | 尽量用英文路径；或统一 UTF-8 |
| 每帧很卡 | 全屏大图带 alpha；每帧 `load` | 见 6.5 / 6.6 |

## 7. 鼠标键盘：Input

### 7.1 核心规则：每帧 `update()` 一次

```cpp
Input in;

while (true)
{
    win.poll();
    in.update();        // ← 每帧一次，把消息队列取空

    if (in.clicked()) { /* ... */ }
    // 其它逻辑
}
```

- `update()` 会把这一帧的所有鼠标/键盘消息**一次性取出来**，并清掉上一帧的"一次性状态"。
- **一帧调用一次**。调用两次，第一次的事件就丢了；不调用，永远收不到输入。
- 不要自己再写 `peekmessage`。`Input::update` 已经把消息取走了，你再取会拿不到。

### 7.2 鼠标

| 调用 | 含义 | 什么时候为 true |
|---|---|---|
| `pos()` | 鼠标当前位置（客户区坐标） | 一直有效 |
| `pressPos()` | 本次按下的位置 | 一直有效（上次按下时记录） |
| `down()` | 这一帧刚按下左键 | 按下那一帧 |
| `up()` | 这一帧刚松开左键 | 松开那一帧 |
| `held()` | 左键一直按着 | 按住期间 |
| `clicked()` | 这一帧完成了一次"点击" | 松开且离按下点 ≤ 6 像素 |
| `doubleClicked()` | 这一帧完成了双击 | 400ms 内、8 像素内的第二次点击 |
| `dragging()` | 按住并移动超过 4 像素 | 拖拽期间 |
| `wheel()` | 这一帧滚轮增量 | 正数 = 上滚，一格 120 |
| `mouseIn(屏幕矩形)` | 鼠标在不在矩形里 | 一直有效 |
| `clickedIn(屏幕矩形)` | 鼠标在矩形里且这一帧点了 | 点击那一帧 |

注意：

- `clicked()` 是在**松开**时判定，不是按下时。这样"按下后拖走再松开"不会误触发。
- `down()` 适合"按住不放"的操作（比如拖拽、连续发射）。
- `held()` 是持续状态，适合"按住加速"。
- `doubleClicked()` 同时也是一次 `clicked()`。
- `pos()` 初始是 `(-1,-1)`，鼠标没动过时不会误判左上角按钮"悬停"。

### 7.3 键盘

| 调用 | 含义 |
|---|---|
| `keyDown(vk)` | 这一帧有没有按下某个虚拟键 |
| `keys()` | 这一帧所有按下的虚拟键码（`std::vector<int>`） |
| `chars()` | 这一帧输入的字符（`std::wstring`，UTF-16；中文/emoji 都在里面） |
| `charsUtf8()` | 把 `chars()` 转成 UTF-8（每次调用都转换，别一帧里反复调） |

虚拟键码常用值：

| 键 | 常量 |
|---|---|
| Esc | `VK_ESCAPE` |
| 回车 | `VK_RETURN` |
| 退格 | `VK_BACK`（字符消息里是 8） |
| 方向键 | `VK_LEFT` / `VK_RIGHT` / `VK_UP` / `VK_DOWN` |
| F11 | `VK_F11` |
| 空格 | `VK_SPACE` |

```cpp
if (in.keyDown(VK_ESCAPE)) break;
if (in.keyDown(VK_F11))    { /* 切全屏 */ }
```

**`keyDown` vs `chars`**：

- 快捷键用 `keyDown`（不依赖输入法、大小写）；
- 输入文字用 `chars`（`WM_CHAR` 已经处理好 Shift、大小写、小键盘、中文）；
- `chars()` 是 `std::wstring`，中文、emoji 都在里面；自己处理时用 `charsUtf8()` 转成 UTF-8；
- 一般不用直接读 `chars()`——交给 `TextInput::update(in)` 就行。

### 7.4 悬停与手型光标

```cpp
bool hover = vp.R(btnRect).contains(in.pos());
in.setHandCursor(hover);          // 悬停时变小手，否则变回箭头
```

`setHandCursor` 会改窗口类的光标，建议**每帧调用**（Windows 在某些情况下会把光标重置）。

### 7.5 鼠标坐标 → 设计坐标

```cpp
// 方式一：先换算
Point p = vp.toDesign(in.pos());
if (vp.inside(in.pos().x, in.pos().y) && btnDesignRect.contains(p)) { ... }

// 方式二：把设计矩形换算成屏幕矩形
if (vp.R(btnDesignRect).contains(in.pos())) { ... }
```

方式二更直接，推荐。

### 7.6 一个完整的悬停/点击例子

```cpp
Rect btn{ 540, 320, 200, 60 };
bool hover = vp.R(btn).contains(in.pos());
in.setHandCursor(hover);

if (hover && in.clicked())
{
    // 点中了
}

vp.fill(btn, hover ? RGB(64, 88, 136) : RGB(34, 42, 62));
vp.frame(btn, RGB(96, 128, 200), 2);
vp.textIn(btn, "开始游戏", 28, RGB(235, 240, 255));
```

### 7.7 中文输入与输入法

`Input` 会把 `WM_CHAR` 收进 `chars()`（UTF-16），`TextInput` 会自动转 UTF-8 并插入。中文输入不需要你额外解码。

输入法候选框的位置可以调：

```cpp
const Rect r = vp.R(输入框设计矩形);
in.setImePosition(r.x + 8, r.bottom());   // 客户区坐标
```

聚焦时每帧调一次也没关系（位置没变时内部不会重复设置）；离开时 `in.clearImePosition()`。完整说明见 [8.7](#87-中文输入ime)。

## 8. 文本输入：TextInput

### 8.1 它只做"编辑逻辑"

`TextInput` 负责：

- 保存文字 `text`（UTF-8，中文一个字占 3 字节，但算 1 个字符）；
- 光标位置 `cursor`；
- 处理字符（打字、退格、中文上屏）、左右键、Home/End、Delete；
- 按类型过滤（只数字 / 任意字符）；
- 长度限制（按"字符"数，中文算 1 个）；
- 数值转换与越界钳制；
- 把光标画在正确的位置（按 UTF-8 字符边界，不会把中文劈成半个）。

它**不负责**：

- 画边框/背景（你自己 `fill` / `frame`）；
- 输入法自己的候选框（那是 Windows 输入法的窗口；本库只负责把候选框挪到输入框旁边）；
- 自动横向滚动（文字太长会超出框，请限制 `maxLen`）。

### 8.2 字段

| 字段 / 方法 | 默认 | 说明 |
|---|---|---|
| `text` | 空 | 当前内容（UTF-8） |
| `cursor` | 0 | 光标在 `text` 里的**字节下标**；不要手改，用左右键 / `placeCursor` / `setText` 维护 |
| `maxLen` | 16 | 最多几个**字符**（中文算 1 个）；0 = 不限 |
| `digitsOnly` | false | 只允许 0-9（中文会被忽略） |
| `password` | false | 每个字符画成 `*` |
| `focused` | true | false = 不响应键盘 |
| `length()` | — | 当前有几个字符（不是字节数） |
| `placeCursor(vp, box, 字号, 鼠标x)` | — | 鼠标点在框里时，把光标放到最近的字符边界 |

### 8.3 每帧处理

```cpp
TextInput name;

// 每帧（在 in.update() 之后）
name.update(in);

if (name.submitted())       // 按了回车
{
    // 取值
    name.consume();         // 清掉"已提交"标记
}

if (name.canceled())        // 按了 Esc
{
    name.consume();
}
```

- `submitted()` / `canceled()` 是**一次性**的，每次 `update` 开头会重置。
- `consume()` 用于"我处理过了，清掉标记"；不调用也会在下一帧自动清。
- 只有 `focused == true` 的输入框才响应键盘。

### 8.4 数值

```cpp
int v = name.number(0);        // 内容非法/为空 → 返回 0
name.clampNumber(0, 100);      // 空/非法不动；否则钳到 [0,100] 并写回
```

`number` 的规则：

- 空 → 返回 `fallback`；
- 允许开头 `+` / `-`；
- 其余必须全是数字；
- 超过 1 亿 → 返回 `fallback`（防溢出）。

`clampNumber` 的规则：

- 空 → 不动；
- 不是数字 → 不动；
- 是数字 → 钳制后 `setText`，用户立刻看到修正结果。

### 8.5 画出来

```cpp
void draw(const Viewport& vp, const Rect& box, int fontSize, COLORREF color,
          bool caretVisible) const;
```

- `box` 是设计坐标；它会把文字垂直居中画在框里，并在 `focused && caretVisible` 时画竖线光标；
- 只画字和光标，**不画边框**。边框你自己画；
- `caretVisible` 通常用时间控制闪烁。

完整例子：

```cpp
TextInput box;
box.maxLen = 8;
box.focused = true;

// 每帧
box.update(in);

// 画
Rect r{ 490, 300, 300, 64 };
vp.fill(r, RGB(24, 30, 44));
vp.frame(r, box.focused ? RGB(120, 180, 255) : RGB(70, 90, 130), 2);

const bool caretOn = ((::GetTickCount() / 500) % 2 == 0);
box.draw(vp, r, 32, RGB(235, 240, 255), caretOn);
```

### 8.6 焦点

如果你有多个输入框，需要自己管理 `focused`：

```cpp
TextInput inputs[3];                    // 三个输入框
Rect      boxes[3] = {                  // 每个输入框在设计坐标里的框
    Rect{ 200, 200, 300, 60 },
    Rect{ 200, 300, 300, 60 },
    Rect{ 200, 400, 300, 60 }
};

// 点击时：把焦点切到点中的那个（点在空白处 = 全部失焦）
for (int i = 0; i < 3; ++i)
    inputs[i].focused = vp.R(boxes[i]).contains(in.pos());

// 每帧
for (auto& t : inputs) t.update(in);
```

`cursor` 是**字节下标**，不是"第几个字"；但左右键、退格、`placeCursor` 都会自动落在字符边界上。`maxLen` 和 `length()` 按**字符**算，所以中文和英文一样，一个算一个。

### 8.7 中文输入（IME）

#### 它到底是怎么进来的

1. 你在输入法里打拼音，输入法自己画候选框；
2. 选字上屏时，Windows 给窗口发 `WM_CHAR`；
3. `Input::update()` 把这一帧的 `WM_CHAR` 收集到 `std::wstring`（UTF-16）；
4. `TextInput::update()` 把它转成 UTF-8，插入到 `text` 的 `cursor` 位置；
5. 光标、退格、删除都按 UTF-8 字符边界走，所以不会出现"删掉半个汉字"。

Unicode 工程和多字节（MBCS）工程都支持：

- Unicode 工程：`WM_CHAR` 直接是宽字符；
- 多字节工程：EasyX 会把一个汉字拆成两条 `WM_CHAR`（GBK 前导字节 + 后继字节），`Input` 会自动拼回去。

> 中文输入建议用 **Unicode 工程**（VS 新建项目的默认选项）。多字节工程在中文系统（代码页 936）也测试通过；如果系统开了“Beta: 使用 UTF-8 提供全球语言支持”，多字节行为可能不同，优先用 Unicode。

#### 最小可运行片段

```cpp
TextInput name;
name.maxLen = 20;          // 20 个字符，中文也算 1 个
name.focused = true;

Rect box{ 390, 300, 500, 72 };   // 设计坐标

// 每帧（在 in.update() 之后）
if (in.clickedIn(vp.R(box)))     // 点框：切焦点 + 按鼠标位置放光标
{
    name.focused = true;
    name.placeCursor(vp, box, 32, in.pos().x);
}

name.update(in);

// 输入法候选框跟着输入框走（位置没变时内部不会重复设置）
if (name.focused)
{
    const Rect r = vp.R(box);
    in.setImePosition(r.x + 8, r.bottom());
}

// 画：框自己画，字和光标交给 TextInput
vp.fill(box, RGB(24, 30, 44));
vp.frame(box, name.focused ? RGB(110, 170, 255) : RGB(70, 90, 130), 2);
name.draw(vp, box, 32, RGB(236, 242, 255), (::GetTickCount() / 500) % 2 == 0);
```

离开输入框时：

```cpp
name.focused = false;
in.clearImePosition();
```

#### 多输入框的焦点

```cpp
TextInput inputs[3];
Rect boxes[3] = { {200,200,300,60}, {200,300,300,60}, {200,400,300,60} };

for (int i = 0; i < 3; ++i)
{
    if (in.clickedIn(vp.R(boxes[i])))
    {
        for (auto& t : inputs) t.focused = false;
        inputs[i].focused = true;
        inputs[i].placeCursor(vp, boxes[i], 28, in.pos().x);
        const Rect r = vp.R(boxes[i]);
        in.setImePosition(r.x + 8, r.bottom());
    }
    inputs[i].update(in);
}
```

#### 已知限制

| 限制 | 说明 |
|---|---|
| 候选框样式 | 由 Windows 输入法决定，本库只能改位置（`setImePosition`） |
| 组字过程 | 拼音下划线/候选窗由输入法画，不在输入框里；上屏后才进 `text` |
| 选中/复制/粘贴 | 本库没做；需要自己加（`GetClipboardData`） |
| 横向滚动 | 没做；`draw` 会裁掉框外内容，超长时请限制 `maxLen` |
| 字体 | 必须选支持中文的字体（宋体、微软雅黑等） |
| 极少数输入法 | 如果不上屏，可以换输入法，或改用系统 `EDIT` 控件 |

### 8.8 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 打不了字 | `focused == false`；或没调 `update` | 设置焦点；每帧调 `update(in)` |
| 回车没反应 | 没检查 `submitted()`，或检查得太晚 | 在 `update` 后立刻检查 |
| 只能输一位 | `maxLen = 1` 或没改默认值 | 设置合适的 `maxLen` |
| 数字框能输字母 | 没设 `digitsOnly` | `digitsOnly = true` |
| 文字画出框 | 没有滚动/裁剪 | 限制 `maxLen` |
| 中文显示成方框 | 字体不支持中文 | 换"宋体"/"微软雅黑" |
| 中文删一半/光标错位 | 手改了 `cursor` 到非字符边界 | 用左右键 / `placeCursor` / `setText` |
| 输入法候选框在屏幕角落 | 没设置 IME 位置 | 聚焦时 `in.setImePosition(r.x, r.bottom())` |
| 中文输不进去 | 窗口没焦点 / 输入法没切到中文 | 先点一下窗口；按 Shift 或 Win+空格切输入法 |

## 9. 页面：Page / Pages

### 9.1 一个页面 = 三个函数

```cpp
struct Page
{
    std::string name;

    std::function<void(const Viewport&)> layout;   // 窗口尺寸变了：算位置
    std::function<void(const Input&)>    update;   // 每帧：处理输入、改状态
    std::function<void(const Viewport&)> draw;     // 每帧：画
};
```

- `layout`：只在窗口尺寸变化时调用（也可以手动调）。用来算按钮/文本框的坐标。
- `update`：每帧调用。处理鼠标键盘、切页面、改数据。
- `draw`：每帧调用。只负责画，不改逻辑。

三个函数都可以不写（留空）。

### 9.2 创建页面

```cpp
Pages pages;

Page& home = pages.add("home");
home.layout = [](const Viewport& vp) {
    // 算 home 页的按钮位置
};
home.update = [](const Input& in) {
    // 处理 home 页的输入
};
home.draw = [](const Viewport& vp) {
    // 画 home 页
};
```

`add` 返回的 `Page&` 在**下一次 `add` 之后仍然有效**（内部用的是 `std::deque`，尾部插入不会让已有元素的引用失效）：

```cpp
Page& a = pages.add("a");
Page& b = pages.add("b");
a.draw = ...;               // ✅ 仍然有效
```

不过还是建议"加完立刻配置"，代码读起来更清楚；将来如果容器换成 `vector` 也不会踩坑。

### 9.3 切页面

```cpp
pages.go("home");
```

- 如果之前调用过 `layoutAll`，`go` 会自动调用目标页面的 `layout`（用最近一次的 `Viewport`）。
- 页面名不存在时，什么也不做。

### 9.4 排版、更新、绘制

```cpp
pages.layoutAll(vp);     // 让所有页面重新排版
pages.update(in);        // 只更新当前页面
pages.draw(vp);          // 只绘制当前页面
```

典型顺序：

```cpp
vp.setDesign(1280, 720);
vp.fit(win.width(), win.height());
pages.layoutAll(vp);
pages.go("home");

while (true)
{
    win.poll();
    in.update();

    pages.update(in);

    win.beginFrame(RGB(10, 10, 14));
    vp.paintLetterbox(RGB(10, 10, 14));
    pages.draw(vp);
    win.endFrame();
}
```

窗口尺寸变化时：

```cpp
win.onResize([&](int w, int h) {
    vp.fit(w, h);
    pages.layoutAll(vp);     // 所有页面重新排版
});
```

### 9.5 页面里的数据放哪

`Page` 只存三个函数，不存你的游戏数据。数据可以：

- 放全局/文件级变量（demo 的做法，简单）；
- 放一个 `struct GameState`，用 lambda 按引用捕获；
- 放 `static` 局部变量（不推荐，难测试）。

```cpp
struct GameState
{
    int score = 0;
    bool paused = false;
};

GameState g_game;       // 全局，活到程序结束

Page& play = pages.add("play");
play.update = [](const Input& in) {
    if (in.keyDown(VK_SPACE)) g_game.paused = !g_game.paused;
};
```

如果捕获局部变量：

```cpp
GameState state;        // 在 main 里
play.update = [&state](const Input& in) { ... };
```

必须保证 `state` 活得比 `pages` 久。`main` 里的局部变量在 `pages` 之前声明、之后析构，通常没问题；但别把 `pages` 做成全局而 `state` 是局部。

### 9.6 完整的两页例子

```cpp
#include "easyx_core.h"
using namespace ezx;

int main()
{
    Window win;
    Viewport vp;
    Input in;
    Pages pages;

    vp.setDesign(1280, 720);

    Page& menu = pages.add("menu");
    menu.layout = [](const Viewport&) { /* 固定坐标，不用算 */ };
    menu.draw = [](const Viewport& vp) {
        vp.textIn(Rect{ 0, 200, 1280, 80 }, "主菜单", 48, RGB(240, 246, 255));
    };

    Page& game = pages.add("game");
    game.draw = [](const Viewport& vp) {
        vp.textIn(Rect{ 0, 200, 1280, 80 }, "游戏", 48, RGB(240, 246, 255));
    };

    win.onResize([&](int w, int h) { vp.fit(w, h); pages.layoutAll(vp); });

    if (!win.open(1024, 640)) return 1;
    vp.fit(win.width(), win.height());
    pages.layoutAll(vp);
    pages.go("menu");

    while (true)
    {
        win.poll();
        in.update();

        // 切页面：直接在 main 里处理最简单
        if (pages.is("menu") && in.keyDown(VK_RETURN)) pages.go("game");
        if (pages.is("game") && in.keyDown(VK_ESCAPE)) pages.go("menu");

        pages.update(in);

        win.beginFrame(RGB(10, 10, 14));
        vp.paintLetterbox(RGB(10, 10, 14));
        pages.draw(vp);
        win.endFrame();
    }
}
```

> lambda 里想访问 `pages` 本身，就按引用捕获 `[&]`，并保证 `pages` 活得够久。上例把切页面放在 `main` 里，避开了这个问题。

### 10.2 手画按钮 `UiButton`

```cpp
struct UiButton
{
    Rect rect;
    std::string label;
    int  fontSize = 30;
    bool hovered = false;

    bool update(const Input& in, const Viewport& vp)
    {
        hovered = vp.R(rect).contains(in.pos());
        return hovered && in.clicked();
    }

    void draw(const Viewport& vp) const
    {
        vp.fill(rect, hovered ? RGB(62, 86, 132) : RGB(34, 42, 62));
        vp.frame(rect, RGB(92, 124, 196), 2);
        vp.textIn(rect, label, fontSize, RGB(236, 242, 255));
    }
};
```

这就是"库不提供按钮"的意思：按钮 = 一个矩形 + 悬停状态 + 点击判断 + 三行绘制。你可以随便加圆角、阴影、图标。

### 10.3 排版 `layoutCommon`

```cpp
const int DESIGN_W = 1280;
const int DESIGN_H = 720;
```

  - 快捷键（demo 方便测试）：`1/2/3` 模式，`4/5/6` 分辨率，`7/8/9/0` 帧率，`C/V` 缩放，`Enter` 应用。

4. 建页面（页面里的绘制函数会用到图片，但此时还没画，所以先后无所谓；不过习惯上先有图再建页面更直观）；
5. 初始 `fit` + `layoutAll` + `go`。

### 10.7 主循环

```cpp
while (g_running)
{
    win.poll();               // ① 窗口
    g_input.update();         // ② 输入

    if (g_input.keyDown(VK_F11))          // ③ 全屏切换
    {
        if (win.mode() == WinMode::Fullscreen)
            win.applyMode(WinMode::Windowed, 1024, 640);
        else
            win.applyMode(WinMode::Fullscreen);
    }

    g_pages.update(g_input);  // ④ 当前页逻辑

    win.beginFrame(RGB(8, 8, 12));        // ⑤ 清屏
    g_vp.paintLetterbox(RGB(8, 8, 12));   //    黑边同色
    g_pages.draw(g_vp);                   // ⑥ 当前页绘制

    win.endFrame();           // ⑦ 翻页 + 动态限帧
}
```

- 先 `poll` 再 `input`：窗口重建后，旧消息已经被 `flushmessage` 清掉，避免误触发。
- `F11` 切全屏会触发 `onResize` → `vp.fit` + `layoutAll`。
- `paintLetterbox` 放在 `beginFrame` 之后、`pages.draw` 之前。
- `endFrame()` 同时负责显示和动态限帧（默认 60 FPS）；`setTargetFps` 可改。

## 11. 编译、运行、排错

### 11.1 安装 EasyX

本项目依赖 EasyX（提供 `graphics.h` 和 `EasyXa.lib` / `EasyXw.lib`）。本机已安装：

```
头文件：D:\VisualStudio2026\VC\Auxiliary\VS\include\graphics.h
库文件：D:\VisualStudio2026\VC\Auxiliary\VS\lib\x64\EasyXa.lib
```

如果你换机器，先装 EasyX（选对应的 VS 版本），装完确认这两个路径存在。

### 11.2 在 Visual Studio 里建工程

1. 新建 → 项目 → **空项目**（C++），平台选 **x64**。
2. 把 `easyx_core.h`、`easyx_core.cpp`、`demo_main.cpp` 复制到工程目录。
3. 右键"源文件"→ 添加 → 现有项，把 `.cpp` 加进去；头文件加到"头文件"里（可选）。
4. 项目属性：

| 设置 | 位置 | 值 |
|---|---|---|
| C++ 语言标准 | C/C++ → 语言 | ISO C++17 或更高 |
| 运行库 | C/C++ → 代码生成 → 运行库 | **多线程 (/MT)**，Debug 和 Release 都改 |
| 源/执行字符集 | C/C++ → 命令行 → 其他选项 | **`/utf-8`** |
| 附加库目录 | 链接器 → 常规 → 附加库目录 | `D:\VisualStudio2026\VC\Auxiliary\VS\lib\x64` |
| 字符集 | 高级 → 字符集 | Unicode 或多字节都行 |
| 子系统 | 链接器 → 系统 → 子系统 | 控制台（默认） |

> ⚠️ **运行库必须选 `/MT`（Debug 和 Release 都选 `/MT`，不要选 `/MTd`）**。
> 本机这套 EasyX 的 `EasyXw.lib` / `EasyXa.lib` 是用 `/MT` 编译的。VS 新建工程默认 Debug 是 `/MDd`、Release 是 `/MD`，所以两个配置都要手动改。
>
> 如果报：
>
> ```
> LNK2038: 检测到“RuntimeLibrary”的不匹配项: 值“MT_StaticRelease”不匹配值“MDd_DynamicDebug”
> LNK2038: 检测到“_ITERATOR_DEBUG_LEVEL”的不匹配项: 值“0”不匹配值“2”
> ```
>
> 如果运行库已经是 `/MT`，却还报：
>
> ```
> 值“MT_StaticRelease”不匹配值“MTd_StaticDebug”
> _ITERATOR_DEBUG_LEVEL：0 对 2
> ```
>
> 说明 Debug 配置的**预处理器定义里还有 `_DEBUG`**。`_DEBUG` 会让 STL 进入调试模式、要求调试版 CRT，即使 `/MT` 也会产生 `MTd` 的指令。
> 解决：Debug 配置的“预处理器定义”去掉 `_DEBUG`，加上 `NDEBUG`；同时把“基本运行时检查”设为默认（不要 `/RTC1`）、“调试信息格式”设为 `程序数据库 (/Zi)`、“支持仅我的代码调试”设为否。改完 **清理解决方案 → 重新生成**。
>
> `/MTd` 也不行（它和 `MT_StaticRelease` 也不匹配）；如果一定要调试版 CRT，需要换一套对应 `/MTd` 编译的 EasyX 库。

> 字符集是 Unicode 时，`easyx.h` 会自动挂 `EasyXw.lib`，**不要再手动加 `EasyXa.lib`**，否则会报 LNK2005 重复定义。字符集是多字节时则用 `EasyXa.lib`。

5. 确保 `res` 在 `.vcxproj` 旁边（VS 调试的默认工作目录）。
6. 按 **F5** 运行。

> **不想逐项设置**：把 `Directory.Build.targets` 复制到项目根目录（和 `.vcxproj` 同级），MSBuild 会自动导入，强制 `/MT`、`/utf-8`、`/U_DEBUG`、加 EasyX 库目录。它只对当前项目生效，不想要了删掉即可。

### 11.4 常见编译/链接错误

| 错误 | 意思 | 解决 |
|---|---|---|
| `C1083: 无法打开包括文件: "graphics.h"` | 没装 EasyX 或头文件路径不对 | 安装 EasyX；或把 `...\VC\Auxiliary\VS\include` 加到附加包含目录 |
| `LNK1104: 无法打开文件 "EasyXa.lib"` | 库文件路径没配 | 加附加库目录（见上） |
| `LNK2038: RuntimeLibrary / _ITERATOR_DEBUG_LEVEL 不匹配` | 运行库选错（Debug 默认 `/MDd`） | 两个配置都改 `/MT`；清理后重新生成 |
| `LNK2019: 无法解析的外部符号 __imp_PostMessageA` 等 | 只包含了 `<graphics.h>`，没包含 `easyx_core.h` | 包含 `easyx_core.h`（它用 `#pragma comment(lib, ...)` 挂了 user32 等库） |
| `LNK2019: 无法解析的外部符号 ...Window::open...` | 没把 `easyx_core.cpp` 加进工程 | 加进去 |
| `LNK2005: 重复定义` | 同时加了 easyx-ui / easyx-btn 的 `.cpp` | 一个工程只留一套 |
| `C4819` / `C2447` / `C1075` | 源文件编码问题 | 另存为"UTF-8 带 BOM"，并加 `/utf-8` |
| 单独中文正常，拼接变量后变成"浣犲ソ" | 字面量被编成 GBK，运行时文本是 UTF-8 | 工程加 `/utf-8` |
| `LNK2019: WinMain` | 子系统设成了 Windows，但入口是 `main` | 子系统改回控制台，或用 `WinMain` |
| `C4201: 非标准扩展: 无名称的结构/联合` | EasyX 头文件里的警告 | 无害，忽略 |

### 11.5 控制台黑框

`demo_main.cpp` 用的是 `int main()`，链接器默认按"控制台程序"处理，所以运行时会多一个黑色控制台窗口。学习阶段建议保留：`printf` 调试很方便。

想去掉黑框，需要：

```cpp
int WINAPI WinMain(HINSTANCE, HINSTANCE, LPSTR, int)
{
    // 原来 main 的内容
}
```

并把链接器 → 系统 → 子系统改成 **Windows (/SUBSYSTEM:WINDOWS)**。这会带来一些入口参数上的差异，初学可以先不管。

### 11.6 发布给别人

至少带上：

```
你的程序.exe
res\
```

`res` 和 exe 放同一层。如果用了 `/MT`，目标机器不需要装 VC++ 运行库；如果用了 `/MD`，对方可能需要。

## 12. 常见坑总表

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| 1 | 图片不显示 | 路径相对工作目录，不是相对源码 | 用绝对路径试；或把 `res` 放到工作目录 |
| 2 | 图片不显示 | 在 `win.open` 之前 `load`/`draw` | 建窗后再加载、绘制 |
| 3 | 图片是黑块 | 带 alpha 的 png 被当不透明画 / 图本身是黑底 | 确认 png 有透明通道；先换 jpg 对比 |
| 4 | 拖动窗口后布局错位 | 没注册 `onResize`，或没重新排版 | `win.onResize` 里 `vp.fit` + `layoutAll` |
| 5 | 按钮点不中 | 设计坐标和屏幕坐标混用 | 用 `vp.R(rect).contains(in.pos())` |
| 6 | 页面引用失效 | 旧实现用 `vector`，加页面会搬家 | 本库已改用 `deque`；若你自己改容器要注意 |
| 7 | 收不到输入 | 没调 `in.update()` | 每帧一次，且在读取前 |
| 8 | 点击触发两次 | 同时用 `down()` 和 `clicked()` | 按钮只用 `clicked()` |
| 9 | 文字位置偏 | `drawText` 的 `(x,y)` 是左上角，不是中心 | 用 `textWidth` 或 `textIn` |
| 10 | 中文乱码 | 源文件不是 UTF-8 BOM | 另存为 UTF-8 BOM |
| 11 | 中文输不进 `TextInput` | 窗口没焦点 / 输入法没切中文 | 先点窗口；Shift 或 Win+空格切输入法 |
| 12 | 输入框文字画出框 | 没有横向滚动/裁剪 | 限制 `maxLen` |
| 12b | 中文删一半 / 光标错位 | 手改了 `cursor` 到非字符边界 | 用左右键、`placeCursor`、`setText` |
| 12c | 输入法候选框在屏幕角落 | 没设置 IME 位置 | 聚焦时 `in.setImePosition(r.x, r.bottom())` |
| 13 | 窗口最大化后每帧闪 | 尺寸回写不对导致反复重建 | 用本库的 `poll`，别自己写 |
| 14 | 最小化后画面异常 | 客户区 0×0 | `poll` 已跳过；绘制前判 `win.width() > 0` |
| 15 | 全屏后任务栏被盖 | 用了 `Fullscreen` | 改用 `WorkArea` |
| 16 | 高分屏字发虚 | 没声明 DPI 感知 | 启动时 `Window::enableDpiAwareness()` |
| 17 | 程序退出时崩 | 全局对象析构顺序 / 重复 `closegraph` | 别手动 `closegraph`；Image 在 Window 之后声明 |
| 18 | 链接报重复定义 | 同时加了多套库的 `.cpp` | 只保留一套 |
| 19 | 每帧很卡 | 全屏 alpha 图 / 每帧加载图片 | 见 6.5、6.6 |
| 20 | 双击 exe 找不到图 | 工作目录变成 exe 目录 | 把 `res` 放 exe 旁边 |

## 13. 改造配方

### 13.1 改背景色

```cpp
win.beginFrame(RGB(28, 30, 38));
```

### 13.2 显示标题

```cpp
vp.textIn(Rect{ 0, 60, 1280, 80 }, "我的游戏", 54, RGB(240, 246, 255));
```

### 13.3 加一个手画按钮

```cpp
Rect btn{ 540, 320, 200, 60 };
const bool hover = vp.R(btn).contains(in.pos());
in.setHandCursor(hover);

if (hover && in.clicked())
{
    // 点击逻辑
}

vp.fill(btn, hover ? RGB(64, 88, 136) : RGB(34, 42, 62));
vp.frame(btn, RGB(96, 128, 200), 2);
vp.textIn(btn, "开始游戏", 28, RGB(235, 240, 255));
```

### 13.4 图片按钮

见 6.7。

### 13.5 背景图 + logo

```cpp
vp.imageCover(g_bg, Rect{ 0, 0, 1280, 720 });
vp.imageFit(g_logo, Rect{ 565, 60, 150, 150 });
```

### 13.6 切换全屏

```cpp
if (in.keyDown(VK_F11))
{
    if (win.mode() == WinMode::Fullscreen)
        win.applyMode(WinMode::Windowed, 1024, 640);
    else
        win.applyMode(WinMode::Fullscreen);
```

### 13.7 加一个页面

```cpp
Page& help = pages.add("help");
help.layout = [](const Viewport& vp) { /* ... */ };
help.update = [](const Input& in) { /* ... */ };
help.draw   = [](const Viewport& vp) {
    vp.textIn(Rect{ 0, 100, 1280, 60 }, "帮助", 44, RGB(240, 246, 255));
};

// 切过去
pages.go("help");
```

### 13.8 显示 FPS

```cpp
#include <cstdio>

DWORD last = ::GetTickCount();
int   frames = 0;
float fps = 0;

// 每帧
++frames;
const DWORD now = ::GetTickCount();
if (now - last >= 500)
{
    fps = frames * 1000.0f / (now - last);
    frames = 0;
    last = now;
}
char buf[64];
std::snprintf(buf, sizeof(buf), "FPS: %.1f", fps);
vp.text(20, 20, buf, 18, RGB(150, 170, 210));
```

### 13.9 点击切换选中

```cpp
bool selected = false;

if (hover && in.clicked()) selected = !selected;

vp.fill(btn, selected ? RGB(64, 88, 136) : (hover ? RGB(48, 64, 96) : RGB(34, 42, 62)));
```

### 13.10 只想要窗口，不想要 Viewport

可以。坐标直接用 `getwidth()/getheight()`：

```cpp
const int w = getwidth();
const int h = getheight();
drawText(w / 2 - 60, h / 2, "居中", 32, color);
```

但窗口一变，布局就得自己重算；`Viewport` 就是帮你省这件事的。

## 14. 术语表

| 术语 | 解释 |
|---|---|
| **EasyX** | 一个 Windows 下的 C++ 图形库，提供 `initgraph`、`putimage`、`outtextxy` 等 |
| **客户区** | 窗口里真正用来画图的区域，不含标题栏和边框 |
| **双缓冲** | 先画到内存里的"后台画布"，最后一次性显示，避免闪烁 |
| **帧** | 主循环转一圈，画一张画面 |
| **FPS** | 每秒帧数 |
| **COLORREF** | Windows 的颜色类型，`RGB(r,g,b)` 生成 |
| **alpha** | 透明度，0 = 全透明，255 = 不透明 |
| **letterbox** | 宽高比不一致时上下或左右留的黑边 |
| **设计分辨率** | 你写坐标时假定的画面大小，如 1280×720 |
| **工作目录** | 程序运行时"相对路径"的基准目录，不等于 exe 所在目录 |
| **RAII** | 对象构造时获取资源、析构时自动释放的 C++ 惯用法 |
| **lambda** | 匿名函数，`[](){}` |
| **LNK2019** | 链接错误：函数声明了但没找到实现 |
| **LNK2038** | 链接错误：两边的编译选项（如运行库）不一致 |
| **C4819** | 编码警告：源文件字符无法用当前代码页表示 |
| **DPI** | 屏幕缩放比例（125%、150%），不处理会发糊 |

## 15. 练习建议

按顺序做，每个都能独立运行：

1. **窗口 + 一行字**：建 1024×640 窗口，画"Hello"，按 Esc 退出。
2. **背景 + logo**：加载 `res/bg.png` 铺满，`res/logo.png` 放中间，窗口缩放不变形。
3. **一个按钮**：画矩形 + 文字，悬停变色，点击后标题变成"点到了"。
4. **图片按钮**：把第 3 题的矩形换成 `drawFit(icon, rect.inset(10))`。
5. **两个页面**：主菜单按回车进"游戏"，游戏里按 Esc 回主菜单。
6. **设置页**：一个只能输数字的输入框，回车后钳制到 0~100 并显示。
7. **中文输入**：做一个昵称输入框，`maxLen = 20`，能输入中英文、Backspace 删一个字、左右键移光标，候选框跟着输入框走。
8. **图片墙**：用 `splitRow` + `splitCol` 把 6 张图排成 3×2，点击某张时高亮。
9. **全屏切换**：F11 在窗口/全屏之间切，布局始终正确。

做完 1~4，你就能改 demo 做自己的小游戏了；5~9 是完整界面的骨架。

## 附：一句话总结

> **建窗（Window）→ 定设计尺寸（Viewport）→ 每帧收输入（Input）→ 清屏（beginFrame）→ 按设计坐标画（文字 / 图片 / 矩形）→ 翻页（endFrame）。**
> 图片就是：**放在 res、建窗后 load、每帧 draw / drawFit / drawCover。**
> 中文就是：**Input 收 WM_CHAR → TextInput 转 UTF-8 插入 → 光标按字符走；候选框用 `setImePosition` 挪到输入框旁边。**
